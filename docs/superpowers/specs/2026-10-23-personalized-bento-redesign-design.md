# MyShop 반응형 · AI 개인화 · 벤토 UI 재설계안

작성일: 2026-10-23
상태: 사용자 승인 (2026-10-23) — 구현 진행

## 1. 요청과 목표

사용자가 지정한 방향은 다음 세 가지다.

- 현재 프로젝트의 반응형 웹 재설계.
- AI 기반 개인화 UI·UX.
- 벤토 그리드 레이아웃.

목표는 사용자가 홈에서 자신의 스타일과 관련된 상품을 발견하고, 상품 탐색·상세·장바구니·주문으로 자연스럽게 이동하는 것이다. 아래 색상, 카드 배치, 개인화 저장 방식과 적용 범위는 코드 조사에 근거한 제안이며 아직 사용자 확정 사항이 아니다.

## 2. 현재 구현에서 확인한 사항

- Next.js App Router, React, TypeScript, Tailwind CSS, Supabase, Zustand를 사용한다.
- 홈은 큰 소개 배너 → 서비스 안내 → 카테고리 → 고정 신상품 → 스타일 진단 배너 순서다. 신상품은 `MOCK_PRODUCTS.slice(0, 4)`다.
- AI 스타일 진단은 4개 답변으로 기존 `/api/style-quiz`를 호출하고 스타일 유형·키워드·코디·상품 ID·팁을 반환한다. 진단 결과는 현재 컴포넌트 메모리에만 존재하며 홈과 연결되지 않는다.
- AI 쇼핑 상담과 스타일 진단은 로그인 및 기존 사용량 제한을 적용한다. 기존 AI 제공자·인증·실패 처리를 유지한다.
- 최근 본 상품은 기존 외부 저장소 구독 훅과 브라우저 저장소를 사용한다. 찜 목록은 로그인한 사용자 API를 사용한다.
- 상품 목록에는 검색어 `q`와 카테고리 `cat`을 함께 사용하는 URL 필터가 있다.
- 브라우저의 390×844 홈 화면에서 문서 폭은 384px이며 가로 넘침이 없었다. 기존 반응형 기능을 기반으로 정보 우선순위와 시각 체계를 재설계한다.
- 상품은 현재 목 카탈로그다. 개인화 UI가 실제 판매 실적, 실시간 트렌드나 사용자 구매 성향을 확보한 것처럼 표현하지 않는다.

## 3. 시각 방향 — 제안

콘셉트: **나를 위한 패션 셀렉트숍**.

- 웜 아이보리 배경, 화이트 카드, 차콜 텍스트, 세이지 그린 포인트를 사용한다. 다크 테마는 기존 기능을 유지하면서 대응 색상을 정의한다.
- 상품 사진과 읽기 쉬운 한글 제목을 중심에 둔다. AI 기능은 작은 아이콘·라벨·분명한 추천 근거로 구분한다.
- 넓은 여백, 얇은 경계선, 20~28px 카드 모서리, 일관된 버튼과 입력 필드를 사용한다. 동일한 카드의 반복을 피하고 콘텐츠 중요도에 따라 면적을 다르게 준다.
- 사용자 추가 요청: 기존 `shaders` 패키지와 `HeroShaderBackground`/`HeroShaderCanvas`를 홈의 메인 벤토 카드에 적극 활용한다. 세이지·차콜 계열로 조정하고 기존 GPU 미지원·모션 감소 정적 배경을 유지한다. 새 화면의 핵심 콘텐츠는 애니메이션 없이도 완전히 보인다.
- 주요 제목·버튼·가격·품절·오류 문구의 대비를 라이트/다크 모두 확인한다. 중요한 상태를 색상만으로 전달하지 않는다.

## 4. 홈 벤토 구성

데스크톱은 최대 약 1280px 콘텐츠 폭과 12컬럼 그리드를 사용한다.

```text
헤더: MyShop / 상품 / 나의 스타일 / 찜·주문 / 테마·계정·장바구니
인사말 + 검색 진입 + 개인화 상태

┌───────────────────────────┬──────────────┬──────────────┐
│ 메인 셀렉션 · 6컬럼        │ 나의 스타일  │ 이어서 보기  │
│ 진단 후: 나의 추천 상품    │ 3컬럼        │ 3컬럼        │
│ 진단 전: 에디터 셀렉션     │ 유형·키워드  │ 최근 본 상품 │
│ 큰 상품 사진 + 탐색 CTA    │ 진단/재진단  │ 상세로 이동  │
├───────────────────────────┴──────────────┼──────────────┤
│ 나를 위한 상품 / 진단 전에는 전체 셀렉션 │ 쇼핑 가이드  │
│ 상품 카드 + 추천 근거                    │ 배송·장바구니│
└──────────────────────────────────────────┴──────────────┘

카테고리 바로가기 → 추가 상품 탐색 → 간결한 푸터
```

- 진단 전에도 상품을 바로 탐색할 수 있다. 진단을 쇼핑의 필수 단계로 만들지 않는다.
- 진단 전 메인 셀렉션은 재고가 있는 현재 카탈로그 중에서 선정하고 ‘에디터 셀렉션’으로 표시한다. 판매량 근거가 없는 ‘베스트’나 ‘급상승’ 표시는 사용하지 않는다.
- ‘나의 스타일’은 미진단 상태에서는 4문항 진단 안내, 진단 후에는 실제 AI 응답의 유형·키워드·코디 요약을 보여준다.
- 최근 본 기록이 없으면 빈 카드 대신 실제 카테고리 탐색을 배치한다. 기록이 생기면 같은 위치에서 최근 본 상품으로 전환한다. 기존 기록은 브라우저 공용이므로 ‘이 기기에서 최근 본 상품’으로 표시하고 계정별 AI 진단 결과와 구분한다.
- ‘쇼핑 가이드’는 기존 배송 기준과 장바구니 이동을 제공한다. 기존 구매·배송 계산을 바꾸지 않는다.
- 홈 카테고리 링크는 실제 `cat` URL로 이동한다.

## 5. AI 개인화 동작과 데이터 경계

### 진단 전

- 개인화 상태를 ‘아직 진단하지 않았어요’로 표시한다.
- 일반 카탈로그 콘텐츠와 최근 본 상품을 사용할 수 있다. 최근 기록 기반 콘텐츠는 AI 추천과 구분해 표시한다.
- AI 진단을 선택한 비로그인 사용자는 기존 로그인 흐름으로 이동하고 완료 후 진단 화면으로 돌아온다.

### 진단 후

1. 사용자가 기존 4문항 진단을 완료한다.
2. 기존 AI API가 성공 응답을 반환하고 유효한 결과일 때만 개인화 상태에 반영한다.
3. 실제 추천 상품 ID의 응답 순서를 유지해 홈 추천을 구성한다. 현재 카탈로그에 없거나 품절인 상품은 추천 구매 대상으로 노출하지 않는다.
4. 실제 진단 결과에 있는 유형·키워드·코디 요약을 근거로 표시한다. 상품별 근거가 없는 상태에서 ‘색상 일치’ 같은 설명을 만들어내지 않는다.
5. 사용자는 재진단 또는 ‘개인화 초기화’를 선택할 수 있다. 마지막 성공 결과는 새 진단이 성공할 때 교체한다.

### 저장 정책 — 구현 제안

- 기존 DB 스키마를 유지하기 위해 이번 범위의 진단 결과는 `sessionStorage`에 저장한다. 동일 탭의 새로고침·홈 이동에서 유지하며, 기기 간 동기화는 제공하지 않는다.
- 결과에는 저장 형식 버전, 로그인 사용자 ID, 진단 시각, 검증된 스타일 결과를 포함한다. 서버의 인증 상태와 소유자가 일치하는 경우만 표시하고 계정 변경·로그아웃 시 지운다.
- 계정이 바뀌거나 로그아웃된 뒤 늦게 도착한 진단 응답은 저장하지 않는다. 로그아웃 요청이 실패하면 기존 계정 상태를 유지하며, 다른 탭에서 계정이 변경된 경우도 표시 전에 현재 소유자를 다시 확인한다.
- 저장소 읽기 실패, 잘못된 JSON, 지원하지 않는 버전, 잘못된 필드는 안전하게 무시한다. SSR 첫 렌더링은 일반 콘텐츠를 사용하고 기존 `useHydrated`/외부 저장소 구독 패턴을 따른다.
- 저장소 쓰기가 실패해도 현재 화면의 성공 결과와 일반 쇼핑은 사용할 수 있다.
- 빈 추천은 진단 실패와 구분한다. 진단 설명은 유지하되 상품 영역에 일반 셀렉션과 상품 탐색 동선을 제공한다.
- 홈 방문·화면 크기 변경·테마 변경으로 AI를 자동 호출하지 않는다. AI 호출은 사용자가 진단 또는 상담을 실행할 때만 발생한다.
- 기존 AI 제공자 선택, 인증, 사용량 제한과 공개 API 응답 형식을 유지한다.

## 6. 반응형과 탐색

- 1024px 이상: 12컬럼 벤토와 데스크톱 헤더. 상세 페이지는 이미지와 구매 정보를 나란히 배치한다.
- 768~1023px: 6컬럼 기준으로 주요 카드와 보조 카드를 재배치한다. 상품·주문 정보는 내용에 따라 1~2열을 사용한다.
- 768px 미만: 메인 셀렉션 → 스타일 → 상품 추천 → 최근 기록 순서의 단일 흐름. 상품 목록은 기본 2열이며, 작은 폭·텍스트 확대에서 읽기 어려우면 1열로 전환한다.
- 모바일 하단에는 홈·상품·스타일·장바구니 진입을 제공한다. 계정·주문·찜은 기존 모바일 메뉴에서도 접근한다. 현재 위치와 접근성 이름을 제공한다.
- 상세·장바구니·결제 화면의 주요 CTA와 모바일 탐색, 상담 창이 겹치지 않도록 공통 하단 여백과 safe-area를 적용한다.
- 상담 창은 작은 화면에서 유효 화면 높이 안에 열고, 입력 영역과 닫기 버튼에 접근할 수 있게 한다.
- 읽기 순서와 키보드 초점 순서는 동일하게 유지한다. 화면 크기나 개인화 결과에 따라 사용 중인 입력·초점 위치를 임의로 이동시키지 않는다.
- 최소 44px 터치 영역, 명시적인 입력 레이블, 키보드 초점, 메뉴 Escape 닫기와 초점 복귀를 확인한다. 모션 감소 설정을 존중한다.

## 7. 적용 화면과 변경 후보

홈만 바뀌고 구매 화면이 다른 제품처럼 보이지 않도록 주요 쇼핑 화면에 같은 시각 체계를 적용한다. 상세·결제·인증 양식은 사용 목적에 맞게 배치하며 벤토 카드의 모양을 억지로 적용하지 않는다.

- 공통: `app/globals.css`, `app/layout.tsx`, `src/components/ui/*` 중 실제 사용 요소 — 색상 토큰, 버튼·입력·상태 표현과 페이지 여백.
- 탐색: `src/components/features/layout/Header.tsx`, `MobileMenu.tsx`, `CartIcon.tsx` 및 필요한 모바일 탐색 컴포넌트. `ScrollToTop.tsx`와 `Toast.tsx`도 모바일 하단 탐색과 겹치지 않도록 확인한다.
- 홈: `app/page.tsx`와 새 홈 전용 벤토·개인화 컴포넌트. 서버 렌더링과 상호작용 영역을 분리한다.
- 개인화: `src/types/style.ts`, 새 저장소 유틸·구독 훅, `StyleQuiz.tsx`, 필요한 로그아웃 정리 지점. API·AI 제공자 구현은 유지한다.
- 상품 목록: `app/products/page.tsx`, `ProductListView.tsx`, `ProductCard.tsx`, `ProductGrid.tsx`, 검색·필터 UI. 기존 `q`/`cat` 동작을 보존한다.
- 상품 상세: `app/products/[id]/page.tsx`, 갤러리·사이즈/수량 선택·관련 상품의 표현과 반응형 배치.
- 구매: `CartView.tsx`, `app/cart/page.tsx`, `app/checkout/page.tsx`, `CheckoutForm.tsx`와 쿠폰·배송 요약 UI.
- 사용자 화면: 로그인·회원가입, 주문 목록/상세, 찜 목록과 관련 로딩·오류·빈 상태. 인증·주문 데이터 처리 규칙을 보존한다.
- 상담: `ChatBot.tsx`의 외관과 모바일 표시. 요청 로직 변경이 필요하면 기존 API 클라이언트/훅 경계를 준수한다.
- 포트폴리오 설명 페이지는 공통 테마 가독성만 확인한다. 설명 콘텐츠 전면 개편은 포함하지 않는다.

정확한 수정 파일은 설계 확정 뒤 실행 계획에서 고정한다. 새 의존성은 추가하지 않고 기존 컴포넌트·유틸·저장소와 테스트 도구를 재사용한다.

## 8. 실행 순서

1. 설계 확정 후 PLANNER가 화면·컴포넌트·데이터 경계별 작업을 계획한다.
2. EXECUTOR가 공통 토큰·헤더·모바일 탐색을 구현한다.
3. 개인화 저장·검증 동작의 회귀 테스트를 작성하고 AI 진단과 홈을 연결한다.
4. 홈 벤토와 상품 목록·상세를 재설계한다.
5. 장바구니·결제·사용자 화면·상담·상태 화면을 같은 디자인으로 정리한다.
6. 자동 검사와 실제 브라우저 검증 후 REVIEWER가 독립적으로 검토한다. 발견된 실제 문제를 수정하고 검증한다.

## 9. 완료 기준과 검증

- 360, 390, 768, 1024, 1440px 폭에서 가로 넘침·콘텐츠 잘림·버튼 겹침 없이 주요 화면을 사용할 수 있다.
- 라이트/다크, 키보드 탐색, 메뉴 열기/닫기·Escape·초점 복귀, 짧은 화면과 모바일 상담창을 확인한다.
- 상품 검색/카테고리 URL, 상품 상세·사이즈/수량, 장바구니, 쿠폰·배송비·총액, 인증과 주문 화면의 기존 동작을 보존한다.
- 개인화의 미진단·성공·빈 결과·실패·품절/누락 상품·새로고침·계정 변경·로그아웃·손상된 저장소 상태를 검증한다.
- AI 성공·실패 UI 검증은 외부 경계 대체를 우선 사용한다. 실제 AI 응답과 인증·DB 연동을 실행하지 않았다면 그 한계를 명시한다.
- 기존 Node 테스트와 새 개인화 경계 테스트, ESLint, TypeScript, Next.js 빌드, `git diff --check`를 실행한다. 현재 기본 `npm` 실행 파일 경로에 문제가 있어 필요하면 설치된 `node_modules`의 CLI를 직접 실행한다.
- 실제 사용자 주문 생성이나 결제는 검증에 포함하지 않는다. 테스트에서 기존 인증·주문 검증을 우회해 제품 코드에 남기지 않는다.
- REVIEWER는 품질 점수와 근거, 실제 발견 사항, 남은 검증 한계를 보고한다. 근거 없는 문제를 만들어 개수를 채우지 않는다.

## 10. 이번 범위의 제약

- 패키지 추가, 환경변수 파일 변경, DB 스키마 변경, 배포 설정 변경, 기존 컴포넌트 삭제, Git commit/push를 수행하지 않는다.
- 추천 엔진 학습, 구매 이력 기반 예측, 사용자 추적 수집, 기기 간 스타일 동기화는 추가하지 않는다.
- 설명되지 않은 구매율·추천 정확도·할인·재고·실시간 인기 수치를 표시하지 않는다.
- 기존 목 카탈로그와 실제 AI 추천 결과를 구분하고, 외부 서비스 검증의 수행 여부를 정확하게 보고한다.

## 11. 사용자 확인 대상

이 문서의 **따뜻한 뉴트럴 톤 + 세이지 포인트**, **쇼핑 홈 중심의 벤토 구성**, **현재 탭·계정에 한정한 AI 진단 결과 개인화**, **주요 쇼핑 화면 전체의 반응형 디자인 적용**을 한 묶음의 제안으로 확인받는다.

사용자는 전체 설계를 승인하고 기존 셰이더를 활용해 그대로 구현하도록 요청했다. 추가 설계 승인이나 커밋·배포 없이 현재 작업 폴더에서 구현과 검증을 진행한다.
